# Changelog

Все значимые изменения в проекте Argus-K.

## [5.8.4] — 2026-09-13

### Добавлено
- Раздел «Чем это отличается от Xkeen и bypass_keenetic»
  в README — для тех, кто выбирает между несколькими
  решениями.
- **Автоопределение сетевых параметров в инсталлере**:
  WAN-интерфейс (через `ndmc`, default route и список
  известных имён LTE/USB/PPPoE), IP роутера и подсеть LAN
  (из `br0`). Пользователь подтверждает или переопределяет
  вручную.
- **Проверка связности WAN** на этапе установки —
  ping через выбранный интерфейс.
- **Fallback-детект `WAN_IF` в `argus-k.sh`** — на случай
  ручного развёртывания без инсталлера.
- **Проверки WAN/LAN в `argus-k-debug.sh`**: существование
  интерфейса, наличие IPv4, наличие `ROUTER_IP` на роутере.
- **Детект совместимости TG-туннеля в ШАГ 2.5**: инсталлер
  автоопределяет существующий туннель (ipset с
  `telegram`/`tg` в имени, iptables-цепочки, процессы
  z2k/z4r/sing-box/mtg/tg-tunnel/mtproto). Логика из 4
  сценариев:
  - нет туннеля, детект пуст → предложить создать через Xray;
  - нет туннеля, но детект что-то нашёл → предупредить о
    возможном конфликте, спросить, продолжать ли;
  - есть туннель, детект что-то нашёл → согласиться, не
    трогать;
  - есть туннель, детект пуст → принять на слово, не
    трогать, подсказать как переключиться позже.
- **Секция «Конфликты TG-туннеля» в `argus-k-debug.sh`**:
  показывает, что нашлось в ipset/iptables/процессах и
  совпадает ли это с `TG_TUNNEL_ENABLED`.
- **Опциональный split routing** (`SPLIT_ROUTING_ENABLED`):
  при скачивании подписки и на старте Argus-K проверяет
  каждый конфиг на наличие domain-based direct-правил. Если
  их нет — препендит одно правило со списком из
  `/opt/etc/argus-k-split-domains.txt` (~210 доменов
  российских сервисов). Конфиги со своим split routing
  (как в дорогих подписках) не трогаются. Идемпотентно.
- Файл `templates/split-domains.txt` — редактируемый список
  доменов для split routing. Скачивается bootstrap'ом в
  `/opt/etc/argus-k-split-domains.txt`. Дополнять можно
  вручную, изменения подхватятся при следующем рестарте.
- Прозрачный туннель для Telegram (XRAY_TG_PREROUTING) —
  отдельная настройка, при которой только трафик к
  Telegram идёт через Xray. Работает независимо от
  режима white list. Основной трафик не затрагивается.
- Поддержка нескольких пользователей Telegram
  (TG_CHAT_IDS — список ID через пробел).
- Команда `/diag` в боте — диагностический отчёт.
- Скрипт `argus-k-debug.sh` с флагом `--tg` для отправки
  отчёта в Telegram.
- Поддержка обходчиков DPI: nfqws, nfqws2, zapret, z2k, b4, z4r.
- GitHub Actions для проверки синтаксиса всех shell-скриптов.
- Автоматическая установка зависимостей через bootstrap.
- Fallback-загрузка Xray с GitHub, если в Entware нет.
- Жёсткая очистка старых экземпляров при старте.

### Исправлено
- Увеличенные таймауты при отправке в Telegram + retry.
- Bootstrap подписки: скачивание напрямую через WAN,
  если Xray ещё не запущен.
- Убраны жёстко прописанные `WAN_IF`, `LOCAL_NET`,
  `ROUTER_IP` — теперь задаются инсталлером.
