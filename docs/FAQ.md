\# FAQ



\## Общие вопросы



\*\*Как это работает?\*\*



Скрипт следит за состоянием LTE-подключения. Определяет,

включён ли у оператора белый список: пробует зайти на

публичные DNS-серверы — если все недоступны, но Yandex

работает, значит whitelist. В этом случае трафик устройств

в сети направляется через VPN.



\*\*Xray что, всегда работает?\*\*



Служба Xray — да, всегда запущена в фоне. Но это не значит,

что весь трафик идёт через VPN. Перенаправление трафика

(редирект) включается только в двух случаях:

1\. Когда мобильный оператор включил white list.

2\. Если включён прозрачный туннель для Telegram — тогда

&#x20;  через VPN идут только IP-адреса Telegram.



В обычном режиме открытого интернета трафик устройств

идёт напрямую, как без всякого VPN.



\*\*А трафик расходуется зря, если VPN не активен?\*\*



Нет. Пока редирект выключен, пакеты идут обычным маршрутом.

Служба Xray в это время ничего не пропускает через туннель —

она просто «стоит наготове», чтобы сразу включиться, когда

это понадобится. Расход трафика не увеличивается.



\*\*Можно ли вообще выключать Xray, когда он не нужен?\*\*



Можно, но не нужно. Во-первых, скрипт не знает заранее,

когда оператор включит white list — если Xray не запущен

в момент переключения, бот не сможет отправить уведомление.

Во-вторых, Xray в простое почти не потребляет ресурсов.



\*\*Нужен ли Telegram-бот?\*\*



Нет. Без бота скрипт работает тихо в фоне.



\*\*Что такое TG-туннель?\*\*



Прозрачное перенаправление только трафика к Telegram через

Xray. Работает всегда — даже когда основной режим открытого

интернета. Полезно, если Telegram должен работать постоянно.



\## Про сеть



\*\*Инсталлер не нашёл WAN-интерфейс — что делать?\*\*



Посмотрите список кандидатов, который инсталлер вывел

перед вопросом. Если в списке нет нужного — проверьте

вручную:



```sh

ip -4 -o addr show

ip route show default

```



Скорее всего, интерфейс — один из:

\- `lte\_br0` — USB LTE-модем (RNDIS);

\- `usb0` / `usb1` — USB LTE-модем (cdc\_ether);

\- `lte0` — встроенный LTE Keenetic;

\- `wwan0` — альтернативное имя;

\- `ppp0` — PPPoE поверх LTE;

\- `eth3` — Ethernet WAN.



\*\*WAN\_IF\_IP меняется при каждой переподключке — это нормально?\*\*



Да. LTE-оператор выдаёт новый IP из пула. Argus-K не

сохраняет WAN\_IF\_IP в конфиг — читает его каждый раз

заново через `ip -4 addr show`.



\*\*ROUTER\_IP не совпадает с реальным — что будет?\*\*



iptables-правила, которые перехватывают DNS от устройств

в сети, будут указывать на несуществующий адрес. Клиенты

не получат DNS через туннель. Поправьте `ROUTER\_IP` и

`LOCAL\_NET` в `/opt/etc/argus-k.sh` и перезапустите

`/opt/etc/init.d/S99argus restart`.



\*\*При включённом прокси российские сайты идут через VPN —

это медленно. Можно как-то их напрямую?\*\*



Да. По умолчанию `SPLIT\_ROUTING\_ENABLED="yes"`, и Argus-K

сам добавляет в каждый скачанный конфиг одно правило со

списком из `/opt/etc/argus-k-split-domains.txt` — это

российские сервисы (Яндекс, VK, Ozon, госуслуги, банки

и т.п.). Они идут напрямую, остальное — через VPN.



Если в твоём конфиге из подписки \*\*уже есть\*\* свои

domain-based direct-правила (у дорогих подписок бывает),

Argus-K ничего не добавит — твои правила приоритетнее.



\*\*Как дополнить список доменов?\*\*



Открой `/opt/etc/argus-k-split-domains.txt` и добавь

нужные домены, по одному на строку, без `domain:`.

Строки с `#` — комментарии. После правки перезапусти:



```sh

/opt/etc/init.d/S99argus restart

```



Argus-K на старте пройдёт по всем конфигам и добавит

новые домены. Конфиги, которые уже содержат domain-based

direct-правило, не будут тронуты — если хочешь

форсировать обновление списка, удали конфиги и запусти

`/update` в боте.



\*\*А если хочу выключить split routing совсем?\*\*



Поставь `SPLIT\_ROUTING\_ENABLED="no"` в

`/opt/etc/argus-k.sh`. Уже добавленные правила останутся —

они не удаляются. Полный откат — перекачать конфиги

из подписки (`/update` в боте).



\*\*Xray падает при старте после включения split routing\*\*



Если в `/opt/var/log/xray/error.log` есть жалобы на

парсинг JSON — отключи split routing:



```sh

sed -i 's|^SPLIT\_ROUTING\_ENABLED=.\*|SPLIT\_ROUTING\_ENABLED="no"|' /opt/etc/argus-k.sh

/opt/etc/init.d/S99argus restart

```



Если ошибка осталась — перекачай конфиги (`/update` в боте),

они придут заново без наших правил.



\## Про подписку



\*\*Провайдер отдаёт заглушку — что делать?\*\*



Сервер не распознал устройство. Проверьте HWID и

UA Device ID. Если не знаете — используйте mitmproxy

(см. \[docs/MITMPROXY.md](MITMPROXY.md)) или обратитесь

в поддержку.



\*\*Займёт ли роутер новый слот в подписке?\*\*



Если HWID и UA Device ID сгенерированы случайно — да,

может занять. Если указаны те же, что у вашего телефона —

не займёт.



\## Про установку



\*\*Как обновить скрипт?\*\*



Повторно запустите bootstrap-команду.



\*\*Как удалить?\*\*



```sh

/opt/etc/init.d/S99argus stop

rm -f /opt/etc/init.d/S99argus /opt/etc/argus-k.sh

rm -f /opt/etc/install-argus.sh /opt/etc/argus-k-debug.sh

rm -f /opt/etc/argus-k-split-domains.txt

rm -rf /tmp/argus-k

```



\*\*Где хранятся конфиги Xray?\*\*



`/opt/etc/xray/configs/`. Скрипт создаёт их сам.



\## Про производительность



\*\*Сколько ресурсов потребляет?\*\*



\- RAM: \~10 МБ на Xray + \~2 МБ на скрипты.

\- CPU: заметно только при первичном сканировании.



\*\*Роутер будет тормозить?\*\*



На Keenetic уровня Giga — нет.



\## Про обходчики DPI



\*\*Какой обходчик выбрать?\*\*



Тот, который у вас уже установлен. Если нет — выберите

«нет» в инсталлере. Argus-K работает и без обходчика.



\*\*Можно ли использовать несколько?\*\*



Нет, Argus-K управляет одним обходчиком через его

init-скрипт.
